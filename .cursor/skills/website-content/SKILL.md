# Website content

## Pflichtreihenfolge

1. Dieses Skill lesen.
2. [knowledge/websites/_shared.md](../../knowledge/websites/_shared.md)
3. Die Site-Datei unter [knowledge/websites/](../../knowledge/websites/README.md) zur Domain
4. Nur **öffentliche** Zeilen in [knowledge/claims.md](../../knowledge/claims.md)
5. Offenes in [knowledge/open-questions.md](../../knowledge/open-questions.md) nicht als Live-Text

Code: zuerst `C:\Githup`, sonst dasselbe Repo über GitHub in Cursor ([knowledge/repos.md](../../knowledge/repos.md)). Information-HUB bleibt die Textquelle; das Website-Repo ist die Umsetzung.

## Was das Skill tut

Steuert Formulierungen, Canonical-URLs, Footer/Impressum und Verbote, bevor HTML/Svelte geändert wird. Es erfindet keine Kundenzahlen, Preise oder Partnerschaften.

## Was es nicht tut

- Keine Antrags-/Eignungstexte (dafür `grants-and-contracts`)
- Keine Portal-Passwörter, AVPQ-Codes, Kundentelefone
- BMA nicht vermarkten
- intern belegte Claims (z. B. >100 Kunden, TMA, Umsatz) nicht auf die Website heben

## Nach der Änderung

1. Canonical-Links prüfen (FirefighterVR = firefightervr.de, nicht firefightervrmobile.de).
2. DE- und EN-Fassungen angleichen, wo die Site zweisprachig ist.
3. GodView nicht zur Headset-App machen; sieben Vertikale auf dem Hub.
4. Im Browser die geänderte Seite und verlinkte Hub-/Produktseiten prüfen.
